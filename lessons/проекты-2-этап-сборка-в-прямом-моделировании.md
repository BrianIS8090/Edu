# Сборка в прямом моделировании — зачем и как

«В Moi3D нет сборки!» — жалоба, которую слышно чаще всего от инженеров, перешедших из Компас-3D или SolidWorks. На самом деле сборка есть, она просто выглядит иначе. В этом уроке — что такое сборка в прямом моделировании, чем она отличается от классической Assembly, как правильно её организовать и почему работа с большой моделью в Moi3D может быть проще, а не сложнее, чем в параметрических CAD. Парные уроки — [Прямое vs параметрическое](lessons/проекты-2-этап-прямое-vs-параметрическое-моделирование.md), [Top-down моделирование](lessons/проекты-2-этап-top-down-моделирование.md), [Организация проекта Moi3D](lessons/проекты-2-этап-организация-проекта-moi3d.md).

---

## Что такое сборка в параметрическом CAD

В Компас-3D, SolidWorks, Fusion «Сборка» — это отдельный тип файла с расширением `.asm` / `.iam`. В нём лежат **ссылки** на файлы деталей, а также:

* Сопряжения (mate) между деталями — «эта грань совпадает с той»
* Иерархия подсборок
* Переменные положения (например, винт можно «открутить», изменив параметр)
* Проверка коллизий, анимация, симуляция

Сама геометрия деталей хранится в других файлах — `.part` / `.ipt`. Сборка только управляет их положением и взаимосвязями.

**Сила такого подхода:** одну деталь (скажем, винт M5) можно использовать в сотне проектов, обновил файл — обновилось везде.

**Слабость:** любое перемещение, замена или правка требует согласования между файлами. При 100+ деталях процесс замедляется, история становится хрупкой.

---

## Что такое сборка в Moi3D

В Moi3D нет отдельного типа «Сборка». Но это не значит, что собирать из деталей нельзя. Механика другая:

* Все объекты живут **в одном файле** `.3dm`.
* **Слои** и **стили** заменяют иерархию подсборок.
* **Имена объектов** заменяют дерево сборки.
* **Группы** (`Select → Group`) объединяют связанные объекты.
* Положение детали — её абсолютные координаты, без сопряжений.

Сборка в Moi3D = один файл со всей моделью, организованный слоями.

### Звучит хаотично?

Нет — если соблюдать дисциплину именования и группировки. В одном файле Moi3D может комфортно жить светильник на 50-80 объектов. Всё, что больше, разбивается на связанные файлы (об этом ниже).

---

## Почему один файл, а не много

Главная причина — **стыки**. Если корпус и крышка живут в одном файле, и корпус «отрезан от крышки» одной плоскостью (см. урок [Top-down моделирование](lessons/проекты-2-этап-top-down-моделирование.md)), их стык **всегда совпадает**.

В параметрическом CAD с отдельными файлами этот стык поддерживается сопряжением, которое может:

* Поломаться при импорте/экспорте
* Потерять ссылку на грань после правки
* Не пересчитаться при смене порядка операций

В Moi3D физически не может быть несоответствия — это одна модель, разделённая на логические зоны.

---

## Слои как структура сборки

Слой в Moi3D — это то, чем в Компасе/SolidWorks является «деталь в подсборке». Типовая структура слоёв для светильника 7Lamp:

```
├── Корпус
│   ├── Корпус-верх
│   └── Корпус-низ
├── Торцы
│   ├── Торец-левый
│   └── Торец-правый
├── Крепёж
│   ├── Винты-M3
│   └── Винты-M4
├── Оптика
│   ├── LED-плата
│   └── Линза
└── Электрика
    ├── Драйвер
    └── Кабель
```

Иерархия — как в Explorer. Создаётся через `View → Layers → Add sublayer`.

**Правила слоёв 7Lamp:**

* Уровней иерархии — не больше 3
* Имена слоёв — по-русски, без сокращений
* Цвет слоя — разный для разных функциональных зон
* Видимость слоя — используется для работы с отдельными деталями

## Стили как свойства деталей

Стиль в Moi3D задаёт цвет объекта, но может нести смысл «материала» в инженерной логике:

| Стиль | Цвет | Что означает для 7Lamp |
|-------|------|-------------------------|
| Алюминий | Серо-металлический | Детали из экструзионного профиля |
| Сталь | Тёмно-серый | Крепёж, кронштейны |
| Пластик-ABS | Матовый белый | 3D-печать или литьё |
| Оптика | Прозрачный | Линзы, рассеиватели |
| Плата | Зелёный | LED-модуль |
| Покупной компонент | Жёлтый | Не моделируется — внешний компонент |

Стиль не делает модель «инженерной сборкой» в параметрическом смысле, но помогает визуально различать материалы и облегчает последующий расчёт веса / стоимости.

## Группы: объединение связанных объектов

Группа `Select → Group` — это «виртуальная деталь», которая двигается, поворачивается и скрывается как одно целое. Используется для:

* **Подсборок.** «Корпус-верх» с фасками, отверстиями, пазами — одна группа.
* **Стандартных компонентов.** Винт с шайбой и гайкой — одна группа.
* **Повторяющихся элементов.** LED-модули 1, 2, 3, 4 — каждая своя группа.

Разница между слоем и группой:

| Признак | Слой | Группа |
|---------|------|--------|
| Видимость | Включается/выключается | Всегда видна, если её слой виден |
| Иерархия | Да, подслои | Плоская (нет подгрупп) |
| Цвет | Объединяет объекты визуально | Не влияет на цвет |
| Движение | Двигается один объект | Двигается вся группа |

**Правило:** слои — для организации, группы — для сборочных единиц.

## Когда один файл становится тесным

Светильник на 100+ объектов или проект с несколькими типоразмерами — уже тяжело в одном файле. Для таких случаев:

### Вариант 1. Связанные файлы

Moi3D поддерживает `File → Reference External File`. Это импорт чужого файла как ссылки — при изменении оригинала модель обновится.

Работает хуже, чем сборка в SolidWorks (нет сопряжений), но для:

* Библиотеки стандартных компонентов
* LED-модулей, которые используются в 10 проектах
* Типовых кронштейнов и крепежа

— достаточно.

### Вариант 2. Модели-спутники

Отдельный файл на каждый типоразмер. Общая часть копируется между файлами. При правке формы — обновляются все копии (ручной процесс).

Применяется в 7Lamp для серий: Line-600, Line-900, Line-1200, Line-1500 — четыре файла, 80% геометрии идентичны.

### Вариант 3. Master-file + экспорты

Один мастер-файл со всеми вариантами, включёнными по слоям. При экспорте на подрядчика — скрывается всё лишнее, выделяется одна деталь → Export Selected.

Подходит для проектов с 2-3 вариантами, которые постоянно синхронизируются.

## Пример из работы 7Lamp

**Задача:** светильник из 4 типов деталей — корпус профильный, крышка, 2 торца, 4 крепёжных уголка. Всего 8 деталей + 20 винтов.

### Организация файла

```
Слой: Корпус
  - Корпус-профиль (1 объект)
  - Крышка (1 объект)
  - Торец-левый (группа из 1 корпуса + 1 кабельного ввода)
  - Торец-правый (группа из 1 корпуса + 1 кабельного ввода)

Слой: Крепёж
  - Уголки (группа, 4 объекта)
  - Винты (группа, 20 винтов, стиль «Сталь»)

Слой: Оптика
  - LED-плата (1 объект, импорт STEP от производителя)
  - Линза (1 объект, экспорт заводской модели)

Слой: Электрика
  - Драйвер (упрощённый блок)
  - Кабель-входной (отрезок кривой, для проверки маршрута)
```

**Итого:** 1 файл, ~35 объектов, 4 слоя + 3 подслоя, 4 группы.

### Как работать с этим

* Хотите посмотреть только корпус? Скройте остальные слои.
* Нужно отправить подрядчику корпус профиля? Выделите объект → `Export Selected` → STEP.
* Меняется длина? Выделяется профиль и торцы → `Stretch`.
* Нужно посчитать вес? Выделение по стилю «Алюминий» → `Object Properties → Mass`.

## Типичные ошибки

| Ошибка | Последствия | Решение |
|--------|-------------|---------|
| Каждая деталь в отдельном файле | Долгая синхронизация, битые ссылки | Один файл, слои |
| Объекты без имён | Через неделю не понять, что где | Именовать каждый объект |
| Всё на одном слое «Default» | Невозможно работать с отдельными деталями | Организовать иерархию слоёв |
| Винты из 20 штук — 20 отдельных объектов | Сложно редактировать, большой файл | Группа «Винты» |
| Импорт STEP без назначения стиля | Объект теряется визуально | Сразу присваивать стиль |
| Стандартные компоненты моделируются заново | Время впустую | Библиотека и Reference External |
| 120+ объектов в одном файле | Тормоза, каша | Разбить на связанные файлы |

## Чеклист сборки в Moi3D

* [ ] Все детали светильника — в одном файле (до 80-100 объектов)
* [ ] Иерархия слоёв выстроена сверху вниз: Корпус → Крепёж → Оптика → Электрика
* [ ] Каждый объект имеет осмысленное имя
* [ ] Стили соответствуют материалам
* [ ] Связанные объекты объединены в группы
* [ ] Стандартные компоненты берутся из библиотеки, а не моделируются
* [ ] Для серии типоразмеров — несколько связанных файлов
* [ ] При экспорте к подрядчику — выделяется только нужная деталь
