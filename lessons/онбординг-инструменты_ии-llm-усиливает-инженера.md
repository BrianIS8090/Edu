# Как LLM усиливает инженера — карта задач и сценариев

Инженер, который считает, что «ChatGPT — это для студентов», теряет 30-50% своей эффективности. Современные LLM (Large Language Models — большие языковые модели) решают задачи инженера: считают по формулам, пишут ТЗ, ищут компоненты, сравнивают подходы, объясняют стандарты. Это не замена инженера, а его усиление — как калькулятор, который не отменяет математику, но делает расчёты в 10 раз быстрее. В этом уроке — карта задач, которые LLM решает в работе инженера-проектировщика 7Lamp. Парные уроки — [Промпты для инженерных задач](lessons/онбординг-инструменты_ии-промпты-для-инженерных-задач.md), [OpenClaw](lessons/ии_и_агенты-инструменты_ии-Оpenclaw.md), [Hermes Agent](lessons/онбординг-инструменты_ии-Hermes_Agent.md).

## Что такое LLM и почему он полезен инженеру

**LLM** — нейросеть, обученная на огромном массиве текстов, включая техническую документацию, стандарты, научные статьи. Она умеет:

* Объяснять сложные концепции простым языком
* Обобщать длинные документы
* Писать структурированные тексты (ТЗ, отчёты, письма)
* Считать по формулам и проверять ваши расчёты
* Сравнивать варианты по заданным критериям
* Переводить между языками и стилями

Чего LLM **не умеет**:

* Гарантировать точность (может ошибаться — всегда проверять)
* Работать в реальном времени с вашим файлом Moi3D
* Видеть текущие цены и наличие на складе
* Знать внутренние стандарты 7Lamp (если не сказать)

## Четыре категории задач инженера

### 1. Генерация текста

* Написать ТЗ по кратким данным
* Составить письмо подрядчику
* Оформить протокол встречи
* Написать раздел паспорта изделия
* Сформулировать рекламацию

LLM здесь — 10× ускорение. Читаете кратко что хотите, получаете первую версию текста. Правите под 7Lamp.

### 2. Поиск и обобщение информации

* Найти даташиты по описанию LED-платы
* Сравнить 3 драйвера Mean Well
* Объяснить, что такое СП 52.13330 в контексте вашего проекта
* Обобщить длинную техническую статью до 3 пунктов

LLM не заменяет поиск, но ускоряет его. Для ищущего в Google по 5-10 ссылок — LLM суммирует, даёт исходные ссылки и позволяет сразу задать уточняющий вопрос.

### 3. Расчёты и проверки

* Посчитать тепловой режим светильника
* Проверить формулу, которую вы помните «плюс-минус»
* Пересчитать из ватт в Люмены для СП 52.13330
* Посчитать IP-класс по описанию конструкции

LLM делает арифметику и алгебру без ошибок. Но **сложные инженерные расчёты проверяйте независимо** — LLM может упустить нюанс.

### 4. Совет и консультация

* Какой лучше: магнит или защёлка для торцевой заглушки?
* Почему в моей модели отверстия оказываются близко к линии гиба?
* Что заказчик имеет в виду под «тёплым светом»?
* Какие подводные камни при монтаже на гипсокартон?

LLM как коллега-технолог — может подсказать опытным взглядом. Без персональной обиды и с любым количеством «глупых вопросов».

## Сценарии применения в 7Lamp

### Сценарий 1. Быстрый старт нового проекта

Пришёл брифинг от заказчика — 2 страницы текста с пожеланиями.

**LLM делает:**

1. Выделяет технические требования (мощность, цветовая температура, IP, материал)
2. Формулирует 10 уточняющих вопросов для заказчика
3. Предлагает 3 варианта концепции

**Экономия:** 1-2 часа чтения и структурирования.

### Сценарий 2. Написание ТЗ подрядчику

У вас набросок: «Нужна деталь из алюминия 2 мм, гнутая, 2 отверстия M6».

**LLM делает:**

1. Разворачивает в полноценное ТЗ: материал, допуски, покрытие, упаковка
2. Добавляет стандартные примечания (направление проката, кромки, и т.д.)
3. Проверяет, не забыли ли чего

**Экономия:** 30-40 минут на ТЗ.

### Сценарий 3. Поиск альтернативного компонента

Нужен драйвер 30 Вт 700 мА для замены Mean Well HLG-40H-700.

**LLM делает:**

1. Перечисляет 5-7 аналогов с разных производителей
2. Даёт сравнение по параметрам (КПД, диммирование, IP, цена)
3. Предупреждает о нюансах (пусковые токи, совместимость)

**Экономия:** 1-2 часа поиска.

### Сценарий 4. Проверка своего расчёта

Посчитали тепловой режим — температура перехода 95°C.

**LLM делает:**

1. Задаёт проверочные вопросы (какую тепловую модель использовали, какой коэффициент теплоотдачи)
2. Указывает на возможные ошибки
3. Предлагает быструю «прикидочную» формулу для проверки

**Экономия:** предотвращение ошибок на этапе, когда их дёшево исправить.

### Сценарий 5. Написание паспорта изделия

Светильник готов, нужен паспорт.

**LLM делает:**

1. Составляет текст по шаблону 7Lamp
2. Описывает технические параметры на основе вашего TЗ
3. Пишет инструкцию по установке
4. Формирует блок по обслуживанию и гарантии

**Экономия:** 2-3 часа на паспорт.

### Сценарий 6. Объяснение стандарта

Заказчик требует «соответствие СП 52.13330».

**LLM делает:**

1. Объясняет, о чём этот стандарт
2. Что в нём применимо к вашему проекту
3. Какие параметры нужно проверить

**Экономия:** 1-2 часа чтения стандарта (читать всё равно потом, но уже целенаправленно).

## Какой LLM выбрать

### Универсальные

| Модель | Плюсы | Минусы |
|--------|-------|--------|
| **Claude (Anthropic)** | Длинный контекст, хорошо понимает задачи | Платный доступ |
| **GPT-4o (OpenAI)** | Богатая экосистема, плагины | Платный, цензурирует часть запросов |
| **Gemini (Google)** | Бесплатный, интеграция с Google-сервисами | Слабее в инженерных задачах |
| **Qwen (Alibaba)** | Бесплатный, хороший русский | Менее стабильный |
| **DeepSeek** | Бесплатный, сильный в коде и расчётах | Менее «разговорный» |

### Стандарт 7Lamp

Для работы инженера-проектировщика в 7Lamp рекомендуются:

1. **Claude** через Anthropic или OpenRouter — для длинных ТЗ и сложных задач
2. **Qwen / DeepSeek** через Z.AI — бесплатные альтернативы для рутины
3. **GPT-4o** через Hermes / OpenClaw — универсальный инструмент

Подробности настройки — в уроках [Hermes Agent](lessons/онбординг-инструменты_ии-Hermes_Agent.md) и [OpenClaw](lessons/ии_и_агенты-инструменты_ии-Оpenclaw.md).

## Ограничения и правила безопасности

### 1. Не доверять без проверки

LLM может:

* Придумать источник, которого нет (halucination)
* Ошибиться в цифре на порядок
* Применить устаревший стандарт
* Спутать похожие компоненты

**Правило:** всё критичное — проверять вручную. Расчёты — перепроверять независимо. Ссылки — открывать и читать.

### 2. Не отдавать конфиденциальные данные

Что НЕ отправляем в публичные LLM:

* ТЗ заказчика под NDA
* Ценовую информацию по заказчикам
* Внутренние стандарты 7Lamp (если есть требование конфиденциальности)
* Персональные данные

Для таких задач — локальные LLM (через Hermes с локальной моделью) или корпоративные аккаунты с подписью NDA.

### 3. Не замещать думать

LLM решает задачи в обычной логике. Сложные ситуации (новые технологии, нестандартные запросы) всё равно требуют вашего анализа. LLM — помощник, не заместитель.

## Пример: полный цикл проекта с LLM

**Задача:** декоративный настенный светильник для ресторана. Требования получены от дизайнера интерьера.

### Этап 1. Разбор ТЗ (10 минут с LLM vs 1 час вручную)

Загрузил брифинг дизайнера (4 страницы). LLM:

* Выделил технические требования: 4000 K, 15-20 Вт, IP44
* Нашёл двусмысленности: «декоративный» не уточнён, размер указан в см и мм
* Сформулировал 8 уточняющих вопросов

### Этап 2. Концепция (30 мин с LLM)

Описал форму в 3 предложениях. LLM:

* Предложил 5 технических подходов (профиль vs листогибочное, монтаж на кронштейн vs саморез)
* Для каждого — плюсы/минусы и ориентировочная сложность
* Рекомендовал 2 варианта для обсуждения с дизайнером

### Этап 3. Моделирование (Moi3D, LLM не подключается)

### Этап 4. Спецификация (20 мин с LLM vs 2 часа)

Подгрузил список компонентов. LLM:

* Нашёл артикулы и рекомендованные поставщики
* Посчитал совокупную стоимость
* Вывел в формат Excel-таблицы

### Этап 5. ТЗ подрядчикам (40 мин с LLM vs 3 часа)

Для каждого подрядчика:

* Сгенерировал текст ТЗ по шаблону
* Указал материалы, допуски, сроки
* Приложил список чертежей

### Этап 6. Паспорт (1 час с LLM vs 4 часа)

* Паспорт изделия по шаблону 7Lamp
* Инструкция по установке
* Раздел по обслуживанию

**Итого:** 3 часа работы с LLM вместо 10 часов без него. Для проекта — это 70% экономии на документации.

## Типовые ошибки

| Ошибка | Последствия | Решение |
|--------|-------------|---------|
| Не проверять результат | Расчёт с ошибкой уходит в производство | Всегда верификация |
| Слишком короткий промпт | Нерелевантный ответ | Подробный контекст |
| Отдавать конфиденциальное | Утечка | Локальные LLM для чувствительного |
| Считать LLM «умнее себя» | Потеря своей экспертизы | LLM — инструмент, не авторитет |
| Использовать 1 модель для всего | Не всегда оптимально | Разные модели под разные задачи |
| Не учиться промптингу | Слабые результаты | См. урок про промпты |
