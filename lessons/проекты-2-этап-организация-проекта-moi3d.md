# Организация проекта в Moi3D — слои, стили, именование

Файл Moi3D без организации — это 50 объектов с именами «Box», «Polysurface», «Curve», «Curve01», которые через неделю невозможно различить. Правильно организованный проект — наоборот: любой объект находится за 5 секунд, любая деталь экспортируется одним кликом, инженер через месяц открывает файл и продолжает работу без боли. В этом уроке — стандарт организации проекта 7Lamp: слои, стили, именование, структура папок. Парный урок — [Сборка в прямом моделировании](lessons/проекты-2-этап-сборка-в-прямом-моделировании.md).

---

## Почему организация критична именно в Moi3D

В параметрическом CAD структура поддерживается автоматически: дерево построения, имена деталей в сборке, автоматические идентификаторы. В Moi3D ничего этого нет — структура полностью зависит от дисциплины инженера.

Без неё:

* Через 3 дня не вспомнить, какая кривая нужна, а какая осталась от эксперимента
* При открытии чужого файла тратится полчаса на «картографирование»
* Экспорт одной детали требует перебора 40 объектов на предмет «этот или не этот»
* Правки модели становятся рискованными — вместе с нужным можно удалить важное

С правильной организацией:

* Любой объект находится за секунды
* Работа над моделью через 2 месяца после паузы — без разбега
* Передача файла коллеге — без сопровождающих объяснений

## Структура папки проекта

Перед тем как открыть Moi3D, организуется **файловая структура**. Стандарт 7Lamp:

```
projects/
└── 2026-04-proj-Name-of-lamp/
    ├── 1-брифинг/
    │   ├── тз.pdf
    │   └── референсы/
    ├── 2-концепт/
    │   ├── скетчи/
    │   └── концепт-v1.3dm
    ├── 3-модель/
    │   ├── основная-v1.3dm    ← рабочий файл
    │   ├── основная-v2.3dm
    │   └── архив-v0.3dm
    ├── 4-чертежи/
    │   ├── КД/
    │   └── сборочный.pdf
    ├── 5-подрядчики/
    │   ├── резка/
    │   ├── гибка/
    │   └── фрезеровка/
    └── 6-паспорт/
        └── паспорт-светильника.pdf
```

Каждая папка соответствует этапу проекта. Имя папки начинается с цифры — тогда проводник сортирует в правильном порядке.

## Именование файла Moi3D

Стандарт имени рабочего файла:

```
<краткое-название>-v<версия>.3dm
```

Примеры:

* `line-1200-v1.3dm` — линейный светильник 1200 мм, первая версия
* `line-1200-v2-коррекция-заказчика.3dm` — после правок
* `moon-декоратив-v3-финал.3dm`

**Правила:**

* Только латиница и кириллица, без пробелов — используйте дефис
* Версия обязательна, даже если одна — всегда `v1` в начале
* При значимых изменениях — новая версия: `v2`, `v3`, `v4`
* Слово «final» / «финал» не используется (всегда будет ещё одна итерация)
* Предыдущие версии не удаляются — переносятся в `/архив/`

## Иерархия слоёв

Слои в Moi3D — это «дерево проекта». Типовая структура для светильника 7Lamp:

```
├── 01-Внешний-абрис  [скрытый после разбивки]
├── 02-Корпус
│   ├── Корпус-верх
│   └── Корпус-низ
├── 03-Крышки
│   ├── Крышка-торцевая-левая
│   └── Крышка-торцевая-правая
├── 04-Крепёж
│   ├── Внутренний (винты M3)
│   └── Монтажный (кронштейны)
├── 05-Оптика
│   ├── LED-модули
│   └── Линзы/рассеиватели
├── 06-Электрика
│   ├── Драйвер
│   └── Провода
├── 07-Покупные-компоненты
└── 99-Служебное  [вспомогательные кривые, эскизы]
```

**Правила слоёв 7Lamp:**

1. **Порядок сверху вниз** — от общего к частному, от корпуса к электронике.
2. **Нумерация префиксом** — слои сортируются по алфавиту, цифры дают порядок.
3. **Не глубже 3 уровней** — 2-й уровень для функциональной зоны, 3-й для отдельных деталей.
4. **Слой `99-Служебное`** — для кривых-помощников, эскизов, временных объектов. Скрывается при финализации.
5. **Цвет слоя** — уникальный для каждой функциональной зоны.

---

## Цвета слоёв: палитра 7Lamp

Цвет слоя — не декор, а визуальная маркировка. Рекомендуемая палитра:

| Зона | Цвет |
|------|------|
| Корпус (алюминий) | Серый (200, 200, 200) |
| Крышки / торцы | Светло-серый (230, 230, 230) |
| Крепёж металлический | Тёмно-серый (80, 80, 80) |
| Оптика | Прозрачный голубой (180, 200, 255) |
| LED / электроника | Зелёный (100, 200, 100) |
| Провода, кабели | Красный (220, 50, 50) |
| Покупные компоненты | Жёлтый (250, 220, 80) |
| Служебное / вспомогательное | Ярко-розовый (255, 100, 255) — чтобы не забыть скрыть |

Ярко-розовый для служебного слоя — специально раздражающий цвет, чтобы инженер сразу замечал, если забыл скрыть эскизы при рендере или экспорте.

## Стили и материалы

Стили в Moi3D дублируют слои по визуальной функции, но несут смысл «материала»:

* **Слой** — где деталь в сборке (корпус, крышка, оптика)
* **Стиль** — из какого материала деталь

Один объект имеет один слой и один стиль. Типовой набор стилей 7Lamp:

```
Материалы/
├── Алюминий-экструзия
├── Алюминий-листовой
├── Сталь-оцинк
├── ABS-пластик
├── PA-пластик-3D-печать
├── PMMA-прозрачный
├── Силикон
└── Покупной (без материала)
```

Стиль даёт:

* Визуальное различие на рендере
* Возможность быстрого подсчёта веса по материалам (выделить все объекты стиля → свойства)
* Фильтрацию при экспорте спецификации

## Именование объектов

Каждый объект в Moi3D должен иметь имя. Типовой шаблон:

```
<функция>-<позиция>
```

Примеры:

* `Корпус-верх`
* `Крышка-торцевая-левая`
* `Винт-M3x8-поз15`
* `Плата-LED-основная`
* `Паз-под-плату`

**Правила:**

* По-русски — легче читается в списке объектов
* Функция всегда первая — при сортировке объекты одного типа рядом
* Номер позиции — только если деталей много однотипных
* Не использовать автоимена типа `Box01`, `Polysurface7`

**Где задать имя:** `Object Properties → Name` (в правой панели свойств).

## Группировка объектов

Связанные объекты объединяются в **группы** (`Select → Group` или `Ctrl+G`):

* Винт M3×8 + шайба + гайка → группа «Винт-в-сборе-M3»
* LED-плата + разъём → группа «LED-модуль»
* 4 крепёжных уголка → группа «Уголки-крепёжные»

Группа работает как одна деталь: при выделении, перемещении, копировании.

**Когда НЕ группировать:**

* Детали, которые должны экспортироваться раздельно (корпус и крышка)
* Объекты, которые нужно править независимо
* Служебные кривые и эскизы — остаются свободными

## Блоки: повторяющиеся элементы

Если в проекте один и тот же объект встречается много раз (например, 20 LED-модулей в линейном светильнике) — используются **блоки** (`Block Manager`).

Блок — это экземпляр одного объекта, размещённый в нескольких местах. Правка одного экземпляра меняет все копии.

**Плюсы:**

* Файл меньше по размеру
* Правка модуля — во всех местах сразу
* Порядок в проекте

**Минусы:**

* Блоки не экспортируются в STEP из Moi3D напрямую — нужно «развалить» (Explode) перед экспортом

Для 7Lamp блоки применяются редко — проще копия через Copy.

## Пример из работы 7Lamp

**Задача:** открыть файл `line-1200-v1.3dm` через 2 месяца и продолжить работу.

### Правильно организованный файл

1. Открываю файл. В панели слоёв вижу структуру:
   ```
   01-Внешний-абрис [скрыт]
   02-Корпус (4 объекта)
   03-Крышки (2 объекта)
   04-Крепёж (12 винтов)
   ...
   ```
2. Каждый объект имеет имя: `Корпус-верх-паз`, `Крышка-торцевая-левая`, `Винт-M3x8-поз-15`.
3. Нужно поправить крышку — включаю только слои `01-Внешний-абрис` (для ориентира) и `03-Крышки`. Работаю.
4. Нужно экспортировать корпус — выделяю по слою → `Export Selected`.

**Итого:** 5-10 минут на вход в работу.

### Хаотичный файл (как делать нельзя)

1. Открываю файл. 40 объектов на слое `Default`, все имена — `Polysurface07`, `Box12`.
2. Нужно поправить крышку — ищу её кликая по объектам.
3. Цвета всех объектов одинаковые, стилей нет.
4. Служебные кривые попадают в рендер.

**Итого:** 30-60 минут на разбор, риск сломать модель.

## Автоматизация: шаблон проекта

Чтобы не настраивать слои каждый раз — используется **шаблон** `.3dm`:

1. Создайте пустой файл.
2. Настройте слои, стили, именование.
3. Сохраните как `7Lamp-template.3dm`.
4. При старте нового проекта — открываете шаблон, сохраняете под новым именем.

Рекомендуется хранить шаблон в общей библиотеке (см. урок [Общая библиотека 7Lamp](lessons/проекты-эффективность-общая-библиотека-7lamp.md)).

## Типовые ошибки

| Ошибка | Как проявляется | Решение |
|--------|-----------------|---------|
| Всё на слое Default | Работа с отдельными деталями невозможна | Организовать иерархию сразу |
| Имена объектов автоматические | Не понять, что где | Именовать каждый объект сразу после создания |
| Служебные кривые на рабочих слоях | Попадают в экспорт и чертёж | Слой `99-Служебное` с ярким цветом |
| Стиль не назначен | Все детали серые, не видно разделения | Присвоить стиль сразу |
| Иерархия слоёв глубже 3 | Путаница, сложно навигация | Не больше 3 уровней |
| Версии не сохраняются | Потерян предыдущий вариант | Всегда `v1`, `v2`, `v3` с перемещением старого в `/архив/` |
