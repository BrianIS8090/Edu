# Работа с большими сборками в Moi3D

Светильник на 20 деталей Moi3D тянет без проблем. Подвесная композиция на 80 деталей — уже замедляется. Архитектурная система с 200+ элементами может вообще не открыться на слабом компьютере. В этом уроке — как организовать большой проект так, чтобы он оставался отзывчивым, какие приёмы оптимизации применять и когда пора разбивать на связанные файлы. Парные уроки — [Сборка в прямом моделировании](lessons/проекты-2-этап-сборка-в-прямом-моделировании.md), [Организация проекта Moi3D](lessons/проекты-2-этап-организация-проекта-moi3d.md).

---

## Симптомы «тяжёлого» файла

Когда файл становится проблемой:

* Открытие — больше 30 секунд
* Поворот модели — рывками, не плавно
* Выделение объекта — задержка 1-3 секунды
* Операции Boolean тормозят или падают
* Moi3D съедает 4+ ГБ оперативной памяти
* Сохранение занимает минуты

Это сигнал — проект вырос из возможностей одного файла. Нужна оптимизация.

---

## Лимиты Moi3D по опыту 7Lamp

| Количество объектов | Поведение |
|---------------------|-----------|
| До 30 | Работает мгновенно |
| 30-80 | Стабильная работа, минимальные тормоза |
| 80-150 | Заметные задержки, нужна оптимизация |
| 150-300 | Серьёзные тормоза, рекомендуется разбивать |
| Больше 300 | Moi3D «задыхается», необходим workflow со связанными файлами |

«Объект» в Moi3D — одно тело (solid). Сборка из 10 винтов M3 — это 10 объектов, а не один.

## Приёмы оптимизации

### 1. Группируйте однотипное

20 винтов — объедините в группу `Винты`. Логически это одна сущность, физически — 20 объектов, но интерфейс работает быстрее, когда группа свёрнута.

### 2. Скрывайте неактивные слои

При работе над крышкой корпуса скройте слои «Электрика», «Оптика», «Крепёж». Moi3D не рендерит скрытые объекты — производительность растёт.

### 3. Удаляйте служебные объекты

После использования вспомогательных кривых и построительных линий — удаляйте их. Оставлять нужно только то, что может понадобиться для правок.

### 4. Упрощайте покупные компоненты

Импорт детального STEP-файла драйвера с шурупами и индикаторами — 40 мелких объектов и 200 поверхностей. Замените на упрощённый блок с габаритными размерами:

```
Было: STEP драйвера, 40 объектов, 5 МБ
Стало: блок-прямоугольник, 1 объект, 50 КБ
```

Для LED-платы, драйвера, коннекторов — упрощённые габаритные модели достаточны. Точная геометрия нужна только для критических зон.

### 5. Избегайте излишних Boolean

Каждая Boolean-операция усложняет геометрию. Вместо серии `Difference` одной командой удалите несколько объектов за раз.

### 6. Сохраняйтесь часто

Moi3D иногда падает на тяжёлых файлах. Привычка `Ctrl+S` каждые 5 минут — норма.

## Когда пора разбивать файл

Если после оптимизации файл всё ещё тяжёлый — разделяйте на связанные файлы. Критерии разбиения:

* **По функциональным блокам** — корпус в одном файле, электроника в другом
* **По типоразмерам** — Line-600, Line-900, Line-1200 в разных файлах с общей библиотекой
* **По физическим модулям** — если изделие состоит из независимых частей (основной корпус + декоративная накладка)

### Вариант A: Мастер-файл + спутники

Основной файл с габаритными размерами всей конструкции. Детальные компоненты в отдельных файлах, ссылаются через `Reference External`.

**Плюсы:**

* Детальный компонент можно править независимо
* Правка отражается во всех мастер-файлах

**Минусы:**

* Ссылки могут «ломаться» при перемещении файлов
* Требует дисциплины с путями

### Вариант B: Независимые файлы + копирование

Каждая серия в своём файле. Общие детали копируются, а не ссылаются.

**Плюсы:**

* Простота
* Нет зависимостей

**Минусы:**

* Правка общей детали — обновление вручную во всех файлах

В 7Lamp чаще используется **вариант B** для серий и **вариант A** для крупных дизайнерских проектов.

## Работа с архитектурными проектами

Светильники 7Lamp иногда встраиваются в архитектурный проект — интерьер, экспозиция, фасад. Там могут быть:

* Стены, потолки, полы (геометрия здания)
* Мебель, предметы интерьера
* Десятки одинаковых светильников

В такой ситуации:

1. **Архитектурная часть — от заказчика**, в отдельном файле
2. **Светильники моделируются в своих файлах**
3. **Объединение** — только для рендера и проверок, не для работы

Для объединения удобен **Rhino** — он лучше переваривает большие сцены, чем Moi3D.

---

## Упрощение для рендера vs для чертежа

Часто нужны две версии одной модели:

### Для рендера (визуализация)

* Все фаски и скругления (`R0,5`) — видны
* Текстуры материалов
* Детальные винты, шурупы, коннекторы
* «Красивые» детали

### Для чертежа и производства

* Крупные фаски в модели, мелкие — примечанием в чертеже
* Упрощённые винты (цилиндр вместо шестигранной головки)
* Только геометрия, нужная для производства

Делайте **две версии файла**:
* `line-1200-v3-модель.3dm` — для рендера
* `line-1200-v3-чертёж.3dm` — для производства (упрощённая)

Сохраняет время на работу.

## Пример: проект из 12 светильников на потолке

**Задача:** подвесная композиция из 12 светильников разной длины на общем каркасе.

### Плохо (один файл)

Все 12 светильников, каркас, подвесы, кабели — в одном файле. Итого 400+ объектов. Moi3D падает каждый час.

### Хорошо (разбиение)

1. `композиция-v1.3dm` — каркас, положения подвесов, упрощённые светильники-прямоугольники
2. `light-550.3dm` — детальный светильник типа A
3. `light-850.3dm` — детальный светильник типа B
4. `light-1200.3dm` — детальный светильник типа C
5. Отдельные DXF — развёртки каркаса, торцов

Мастер-файл легко открывается, детальные модели правятся независимо.

## Типовые ошибки

| Ошибка | Последствия | Решение |
|--------|-------------|---------|
| 300 объектов в одном файле | Moi3D падает | Разбить на связанные |
| Детальные модели покупных компонентов | 10× раздувание файла | Упрощать до габаритов |
| Не сохраняться при работе с тяжёлым файлом | Потеря часа работы при падении | Ctrl+S каждые 5 мин |
| Не удалять служебные кривые | Каша, тормоза | Чистить после каждого этапа |
| Открывать файл без предварительного просмотра в проводнике | Не видно, какой тяжёлый | Сортировка по размеру в папке |
| Импорт в Moi3D архитектурной модели | Тормоза, падения | Работать в Rhino |

## Чеклист работы с большой сборкой

* [ ] Файл меньше 50 МБ при больших размерах — скорее всего всё ок
* [ ] Меньше 100-150 объектов в активной работе
* [ ] Покупные компоненты упрощены до габаритов
* [ ] Служебные кривые на отдельном слое, удаляются после использования
* [ ] Однотипные объекты собраны в группы
* [ ] Файл сохраняется каждые 5 минут
* [ ] Для проектов 200+ объектов — workflow со связанными файлами
* [ ] Для архитектурных моделей — Rhino, а не Moi3D
