# Генерация ТЗ и документации через ИИ

Инженер-проектировщик 7Lamp за один проект пишет: ТЗ заказчику, ТЗ подрядчикам (3-5 штук), паспорт изделия, инструкцию по монтажу, коммерческое предложение, отчёт о выполненной работе. Суммарно — 15-30 часов на документацию. С правильным использованием LLM — 4-8 часов. В этом уроке — как применять ИИ для генерации документации без потери качества и соответствия стандартам 7Lamp. Парные уроки — [Промпты для инженерных задач](lessons/онбординг-инструменты_ии-промпты-для-инженерных-задач.md), [Шаблонизация рутины](lessons/проекты-эффективность-шаблонизация-рутины.md).

| Документ | Объём | Частота | Сложность |
|----------|-------|---------|-----------|
| ТЗ заказчику | 2-5 стр. | 1× на проект | Высокая |
| ТЗ подрядчикам | 1-3 стр. | 3-10× на проект | Средняя |
| Паспорт изделия | 4-10 стр. | 1× на проект | Высокая |

## Общий workflow генерации документа

### Шаг 1. Контекст проекта

Подготовьте **контекстный блок** — набор данных, который LLM будет использовать для всех документов:

```
# Проект: Декоративный светильник "Волна"

## Заказчик
Ресторан "Палитра", Москва

## Технические параметры
- Длина 600 мм, ширина 200 мм, высота 50 мм
- Мощность 18 Вт
- Цветовая температура 4000 K
- CRI > 90
- IP44 (под козырьком ресторана)
- Питание 220 В AC

## Материалы
- Корпус: алюминий 6063-T5, анодирование
- Рассеиватель: матовый поликарбонат 2,5 мм
- LED: Samsung LM301B
- Драйвер: Mean Well HLG-40H-C350A

## Срок
- Проектирование: апрель 2026
- Производство: май 2026
- Монтаж: июнь 2026

## Цена для заказчика
95 000 ₽ за единицу
```

Этот блок используется в начале каждого промпта.

### Шаг 2. Выбор шаблона

В общей библиотеке 7Lamp есть шаблоны для каждого типа документа:

* `ТЗ-zakazchiku.md`
* `ТЗ-podryadchiku-rezka.md`
* `Passport-shablon.md`
* `KP-shablon.md`
* `Instruktsiya-montazha.md`

LLM дописывает содержимое в шаблон.

### Шаг 3. Промпт с шаблоном

```
Ты инженер 7Lamp. Напиши документ по шаблону.

<контекст проекта>

<шаблон документа>

Задача:
Заполни все разделы шаблона на основе контекста проекта.
Используй стандартные формулировки 7Lamp.
Объём: как в шаблоне.
```

### Шаг 4. Первая версия и правки

LLM выдаёт первый черновик. Вы:

1. Читаете от начала до конца
2. Отмечаете неточности, пропуски, неудачные формулировки
3. Задаёте LLM доработки конкретными указаниями

### Шаг 5. Финализация и оформление

Полученный текст:

1. Копируется в Word по шаблону 7Lamp
2. Применяется корпоративное форматирование
3. Добавляются схемы, картинки, чертежи
4. Проверяется на соответствие стандарту

## Пример: генерация ТЗ подрядчику

**Задача:** ТЗ для лазерной резки корпуса светильника.

**Промпт:**

```
Ты инженер 7Lamp, пишу ТЗ подрядчику по лазерной резке.

Контекст:
- Проект "Волна"
- Деталь: корпус светильника
- Материал: алюминий 5052 H32, 2 мм
- Количество: 50 шт
- Форма: прямоугольная с вырезами (DXF приложен)
- Допуск: ±0,1 мм
- Срок изготовления: 5 рабочих дней

Стандартные требования 7Lamp:
- Направление проката — поперёк длинной стороны
- Удаление заусенцев: обязательно
- Упаковка: в картонную коробку, каждая деталь в пакете
- Сопроводительная документация: акт приёмки
- Маркировка: номер партии лазерной гравировкой

Формат ТЗ:
1. Шапка (получатель, отправитель, дата)
2. Описание задачи
3. Технические требования
4. Материалы
5. Качество и контроль
6. Сроки
7. Упаковка и доставка
8. Стоимость
9. Подпись

Дополнительно: в каждом разделе использовать деловой стиль, без излишнего формализма.
```

**Результат:** готовый ТЗ на 1 страницу за 2 минуты работы LLM. Инженер проверяет, адаптирует, отправляет.

## Пример: паспорт изделия

Паспорт — большой документ. Разбивайте по разделам, чтобы не перегружать LLM.

### Раздел 1. Общие сведения

```
Напиши раздел "Общие сведения" для паспорта светильника.

Исходные данные:
<контекст проекта>

В разделе должно быть:
- Наименование изделия
- Назначение
- Область применения
- Условия эксплуатации

Стандарт оформления: в соответствии с ТР ТС 004/2011.
```

### Раздел 2. Технические характеристики

```
Напиши раздел "Технические характеристики" в виде таблицы.

<контекст проекта>

В таблице: параметр | значение | единица измерения | примечание

Обязательные параметры:
- Номинальная мощность
- Напряжение питания
- Частота
- Цветовая температура
- Световой поток
- CRI
- Класс защиты IP
- Класс защиты от поражения током
- Температурный диапазон работы
- Средний срок службы
- Масса
- Габаритные размеры
```

## Пример: инструкция по монтажу

Инструкция по монтажу должна быть **для человека с отвёрткой**, не для инженера.

```
Напиши инструкцию по установке светильника для монтажника-электрика.

Светильник:
<контекст проекта>

Требования к инструкции:
- Аудитория: электромонтажник с базовой квалификацией
- Язык: простой, без технических деталей, которые не нужны на монтаже
- Структура: пронумерованные шаги
- Обязательно: требования безопасности (отключение питания, защитные очки)
- Упомянуть требуемый инструмент (конкретный список)
- Упомянуть проверки после установки (работа, плотность затяжки)
- Объём: 1-2 страницы

Не описывать схему электроники изнутри — это для сервисного инженера.
```

## Корпоративный стиль 7Lamp

LLM по умолчанию пишет в «нейтральном» стиле. Для 7Lamp:

### Что предпочитается

* Деловой тон, без фамильярности
* Конкретика и цифры
* Структура: заголовки, списки, таблицы
* Без «мы рады предложить», «мы стремимся»

### Что исключается

* Эмодзи
* Восклицательные знаки в деловой переписке
* Абстракции без конкретики
* Сокращения и жаргон без расшифровки
* Излишний канцеляризм («осуществить проведение мероприятий»)

**Правило в промпте:**

```
Стиль: деловой, конкретный, без воды.
Не использовать: эмодзи, восклицательные знаки, абстракции, канцеляризм.
Использовать: конкретные цифры, структуру, активный залог.
```

## Проверка перед отправкой

Любой документ от LLM проходит финальную проверку:

### Чеклист

* [ ] Все цифры и данные соответствуют проекту
* [ ] Нет противоречий с контекстом
* [ ] Формулировки корректны (нет «LLM-шаблонов» типа «в данном документе»)
* [ ] Соответствует стандарту 7Lamp
* [ ] Оформлено в Word по корпоративному шаблону
* [ ] Добавлены схемы, картинки, приложения
* [ ] Проверена орфография и пунктуация
* [ ] Согласовано с руководителем (для критичных)

**Никогда не отправлять документ без личной проверки.** LLM может ошибиться, и подпись под документом — ваша.

---

## Типовые ошибки

| Ошибка | Последствия | Решение |
|--------|-------------|---------|
| Отправка без проверки | Ошибки в финальных документах | Обязательная проверка |
| Нет контекста проекта | Общий неподходящий текст | Подробный контекстный блок |
| Не указан стиль | «Книжный» LLM-язык | Явно указать деловой стиль |
| Одним промптом весь паспорт | Низкое качество | По разделам |
| Игнор шаблонов 7Lamp | Разнобой в документации | Только через шаблоны |
| Не сохраняют промпты | Заново изобретают | Библиотека промптов |

## Чеклист генерации документа

* [ ] Собран контекст проекта (контекстный блок)
* [ ] Выбран шаблон из общей библиотеки 7Lamp
* [ ] Промпт содержит стиль и формат
* [ ] Для больших документов — разбивка по разделам
* [ ] Первая версия получена и прочитана
* [ ] Уточнения и правки сделаны итеративно
* [ ] Финальный текст проверен построчно
* [ ] Оформлен в корпоративном шаблоне 7Lamp
* [ ] Согласован с руководителем (если нужно)
