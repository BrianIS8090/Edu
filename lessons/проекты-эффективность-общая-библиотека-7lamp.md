# Общая библиотека 7Lamp — регламент и работа

Личная библиотека — ваш капитал. Общая библиотека 7Lamp — капитал компании. Это централизованное хранилище типовых решений, профилей, шаблонов, стандартов, которыми пользуются все инженеры. Без общей библиотеки каждый изобретает велосипед заново, решения противоречат друг другу, и проект зависит от того, «кто в команде». В этом уроке — что в ней хранится, как правильно её использовать и как пополнять. Парный урок — [Личная библиотека инженера](lessons/проекты-эффективность-личная-библиотека-инженера.md).

---

## Чем общая библиотека отличается от личной

| Признак | Личная | Общая |
|---------|--------|-------|
| Доступ | Только ваш | У всех инженеров 7Lamp |
| Структура | По вашему усмотрению | Стандартизована |
| Пополнение | Когда хотите | По регламенту |
| Содержимое | Ваши находки | Стандарты компании |
| Обязательность использования | Рекомендательно | Обязательно |

Общая библиотека — это **источник правды** для проектов 7Lamp. Если в общей есть типовой кронштейн — использовать его, а не моделировать свой. Если есть стандартный профиль — брать его, а не изобретать новый.

## Что хранится в общей библиотеке 7Lamp

### 1. Каталог профилей

Все экструдированные профили, которые когда-либо использовались в 7Lamp или доступны у проверенных поставщиков:

* STEP-модель сечения на 1 м
* Чертёж сечения с размерами
* Марка сплава (обычно 6063-T5)
* Поставщик и код заказа
* Минимальная партия
* Ориентировочная цена

Пример: `PRO-015-Line30x40-Double-Chamber.step` — двухкамерный профиль 30×40 мм, производитель LEDPred, артикул LP-LINE-3040-2C.

### 2. Стандартные компоненты

LED-модули, драйверы, коннекторы, оптика — всё в упрощённом виде (габариты) и детальном (точная модель производителя):

* `LED-001-Samsung-LM301B-10x50.step` — LED-модуль 10×50 мм
* `DRV-012-MeanWell-HLG-40H.step` — драйвер Mean Well 40 Вт
* `OPT-005-Ledil-Strada-IP.step` — оптика Ledil Strada

Правило: никогда не рисовать с нуля то, что производитель предоставляет сам.

### 3. Типовые узлы 7Lamp

Крепёжные узлы, подвесы, торцевые заглушки — проверенные решения:

* `UZ-001-Podves-tros-standart.3dm`
* `UZ-005-Krepezh-fasadnyy.3dm`
* `UZ-010-Vnutrenniy-kabelnyy.3dm`

### 4. Шаблоны документов

* Шаблон Moi3D с настроенными слоями и стилями
* Шаблон чертежа по ЕСКД с рамкой 7Lamp
* Шаблон паспорта изделия
* Шаблон коммерческого предложения
* Шаблон заявки в производство

### 5. Нормативные документы

Коллекция ГОСТ, СП, ТУ, которые применяются в проектах 7Lamp:

* ГОСТ 24705 — Резьба метрическая
* ГОСТ 11284 — Сквозные отверстия
* ГОСТ 14254 (IEC 60529) — IP-защита
* ТР ТС 004/2011 — Безопасность
* СП 52.13330 — Освещение (для справки светотехника)

### 6. Стандарты оформления

* Регламент чертежей 7Lamp
* Стандарт именования файлов
* Цветовая палитра слоёв Moi3D
* Типовые примечания для КД

### 7. Наработки по материалам

* Таблицы сплавов алюминия и их свойств
* Справочник по пластикам для 3D-печати
* Список проверенных подрядчиков по технологиям

## Где физически хранится

В 7Lamp общая библиотека живёт:

1. **На сетевом диске компании** — основной доступ, всегда актуально
2. **В Git-репозитории** — для скриптов, шаблонов, чертежей (версионирование)
3. **В ERP-системе 7Lamp** — справочники компонентов (цены, склад)

Доступ выдаётся при приёме инженера на работу. Если доступа нет — запросить у руководителя.

## Регламент использования

### Использовать — обязательно

1. **Перед моделированием** — проверить, есть ли готовое решение в общей библиотеке
2. **Для стандартных компонентов** — брать только из общей библиотеки, не с сайтов производителей (там версии могут быть неактуальны)
3. **Для шаблонов чертежей** — только общий шаблон, свой «личный» запрещён

### Копировать — можно

Файлы из общей библиотеки копируются в рабочий проект. Изменения в рабочей копии — нормально, но исходник не трогаем.

### Менять — через регламент

Если нашли ошибку в компоненте общей библиотеки или хотите добавить свой — см. раздел «Пополнение» ниже. Просто перезаписать файл — нельзя.

## Пополнение общей библиотеки

### Шаг 1. Соответствие критериям

Что принимается в общую библиотеку:

* **Переиспользуемое решение** — использовалось 2+ раза в разных проектах
* **Проверенное** — прошло минимум одну реализацию на объекте
* **Оформленное** — с чертежом, паспортом, инструкцией по применению
* **Стандартизированное** — имя по шаблону, структура папок правильная

Что НЕ принимается:

* Уникальные решения для одного проекта
* Экспериментальные наработки без проверки
* Плохо документированные модели
* Дубликаты существующего

### Шаг 2. Подготовка

Кандидат на пополнение готовит:

1. Файлы (`.3dm`, `.step`, `.dxf`, `.pdf` в нужных форматах)
2. Описание в формате `README.md` — что это, зачем, как применять
3. Скриншот для индекса

### Шаг 3. Согласование

1. Предложение в чате команды: «Предлагаю добавить в библиотеку — такой-то узел»
2. Обратная связь от коллег
3. Решение главного инженера или техлида

### Шаг 4. Добавление

Файлы загружаются в правильную папку общей библиотеки. Обновляется индекс (каталог).

### Шаг 5. Оповещение

Новости: «Добавлен в общую библиотеку новый узел — теперь используем его вместо…». Письмо / сообщение команде.

## Индекс общей библиотеки

Общая библиотека без индекса — мёртвый архив. Индекс — это каталог с:

* Превью-скриншотом каждого компонента
* Кратким описанием
* Параметрами (габариты, материал, стоимость)
* Ссылкой на файл

В 7Lamp индекс ведётся в виде:

1. **Markdown-файл** `INDEX.md` в каждой подпапке (быстрый просмотр)
2. **HTML-каталог** с превьюшками (генерируется скриптом)
3. **Excel-реестр** для компонентов с ценами

Без индекса инженеры не находят нужное — и начинают изобретать своё. Так библиотека умирает.

## Пример использования

**Задача:** проект линейного светильника Line-1200 для интерьера офиса.

### Без общей библиотеки

1. Смотрю у производителя профили → скачиваю STEP с неактуального сайта
2. Рисую свою торцевую заглушку (которая где-то уже была в другом проекте)
3. Оформляю чертёж в «своём» шаблоне
4. Заполняю паспорт по памяти (половина полей пропущена)

**Результат:** проект несистемный, коллеги не могут его поддержать при болезни.

### С общей библиотекой

1. Открываю каталог профилей → выбираю `PRO-015-Line30x40`
2. Беру стандартные торцы `ZG-003-PRO30-Standart`
3. Открываю шаблон Moi3D 7Lamp — слои и стили уже настроены
4. Чертёж по шаблону 7Lamp — рамка и штамп уже есть
5. Паспорт по шаблону 7Lamp — все поля заполняю по пунктам

**Результат:** проект в стандарте компании, любой коллега может подхватить.

## Типовые ошибки

| Ошибка | Последствия | Решение |
|--------|-------------|---------|
| Не используют общую библиотеку | Каждый инженер в своём стандарте | Требование руководства |
| Используют старые версии компонентов | Несоответствие в документах | Всегда проверять актуальность |
| Правят файлы общей библиотеки напрямую | Ломают работу коллегам | Только через регламент |
| Не пополняют библиотеку | Она устаревает | Привычка после каждого проекта |
| Добавляют без документации | Никто не знает, как применять | README.md обязателен |
| Нет индекса | Файлов много, находятся плохо | Поддерживать INDEX.md |

## Чеклист работы с общей библиотекой

* [ ] Доступ к общей библиотеке настроен
* [ ] Знаете, где лежат основные папки (профили, шаблоны, узлы)
* [ ] Перед моделированием всегда проверяете наличие готового
* [ ] Используете общий шаблон Moi3D и чертежа
* [ ] Стандартные компоненты — только из общей библиотеки
* [ ] После проекта — осмотр: что можно отдать в общую
* [ ] Не изменяете файлы общей библиотеки напрямую
* [ ] При предложении нового — соблюдаете регламент
