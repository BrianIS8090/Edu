# Гайд по написанию уроков: Продажи и маркетинг

Дополнение к основному [writing-guide.md](references/writing-guide.md) для авторов уроков категории **Продажи**. Специфика: аудитория — менеджеры по продажам, а не инженеры.

---

## Аудитория уроков по продажам

**Менеджеры по продажам 7Lamp** — люди с коммерческим мышлением, не инженеры. Они знают продукт на уровне каталога, но не на уровне физики света.

**Что это значит для автора:**

- Технические термины объясняйте через выгоду для клиента, а не через физику
- Вместо «CRI > 90» — «цветопередача CRI > 90 означает, что корпоративные цвета выглядят одинаково в любом филиале»
- Давайте готовые речевые модули и фразы-крючки
- Каждый блок теории привязывайте к реальной ситуации продажи

---

## Структура урока по продажам

Уроки по продажам следуют общей структуре (frontmatter → H1 → вводный абзац → секции → вопросы), но имеют свои особенности.

### Frontmatter

```markdown
---
title: Название урока
category: Продажи
subcategory: Типология клиентов
tags: [продажи, тег2, тег3]
---
```

Категория всегда `Продажи`. Существующие подкатегории:

- **Ассортимент продукции** — характеристики и позиционирование продуктовых линеек
- **Типология клиентов** — сегменты рынка, мотивация, цикл сделки

### Именование файла

```
lessons/продажи-<название-через-дефисы>.md
```

Примеры:
- `продажи-целевые-аудитории.md`
- `продажи-работа-с-возражениями.md`
- `продажи-каталог-серий-line.md`

## Ключевые элементы урока по продажам

### 1. Карточка сегмента / продукта

Каждый сегмент клиентов или продукт начинается со структурированной карточки в виде таблицы.

**Для сегмента клиентов:**

```markdown
## Название сегмента

**Роли:** конкретные должности контактных лиц

| Параметр | Значение |
| --- | --- |
| Цикл сделки | X–Y месяцев |
| Стадия входа | На каком этапе проекта появляется |
| Тип мышления | Как принимает решения |
```

**Для продукта:**

```markdown
## Название серии

| Параметр | Значение |
| --- | --- |
| Тип | Линейный / точечный / трековый / ... |
| Применение | Офис, ритейл, архитектура |
| Ключевая особенность | Что отличает от конкурентов |
```

### 2. Блок «Что продаём»

Список из 2-4 ценностных предложений. Каждое — жирный заголовок + раскрытие в одно предложение.

```markdown
### Что продаём

* **Свобода творчества** — кастомные сечения, плавная гибка, 3D-печать узлов
* **Сервис «под ключ»** — менеджер берёт расчёт освещённости на себя
```

Ценности формулируются **с позиции клиента**, а не производителя.

| Неправильно (наша позиция) | Правильно (позиция клиента) |
|---|---|
| У нас современное производство | Любую форму соберём по вашему эскизу |
| Мы используем качественные LED | Стабильный цвет света через 5 лет |
| У нас быстрая логистика | Светильники приедут день в день |

### 3. Блок «Как это звучит в разговоре»

Диалоговые примеры — ключевой элемент уроков по продажам. Показывают, как применить теорию в живом разговоре.

```markdown
### Как это звучит в разговоре

> **Клиент:** «В проекте заложен итальянский профиль, но бюджет не тянет.»
>
> **Менеджер:** «Присылайте спецификацию. Мы подберём аналог — визуально один в один, но оптимизируем смету на 15–25%.»
```

**Правила диалогов:**

- Клиент говорит **реальную фразу** — не абстрактную, а конкретную
- Менеджер отвечает **действием** — не общими словами, а конкретным предложением
- Диалог заканчивается тем, что менеджер берёт инициативу
- Один диалог на каждый сегмент или ситуацию

### 4. Фразы-крючки

Краткая формула для запоминания. Выделяется как цитата после каждого блока.

```markdown
> Правило: архитектору продаём **свободу творчества**. Фраза-крючок: *«Рисуйте любую форму — наше производство соберёт это в точности.»*
```

Фраза-крючок — это **одно предложение**, которое менеджер может использовать дословно.

### 5. Сводные таблицы

В конце крупных секций — сводная таблица для быстрого обзора.

```markdown
## Сводная таблица

| Аудитория | Цикл сделки | Что продаём | Стадия входа |
| --- | --- | --- | --- |
| Архитекторы | 6–18+ мес. | Свободу творчества | Стадия П |
| Генподрядчики | 3–9 мес. | Экономию и сроки | Стадия РД |
```

### 6. Практические ситуации

Перед вопросами для закрепления — 2-3 разбора ситуаций.

```markdown
## Практика: разбор ситуаций

### Ситуация 1

Описание конкретной ситуации из практики продаж.

**Вопрос:** Что делать? Какие аргументы использовать?
```

Ситуации должны быть **правдоподобными** — реальные звонки, встречи, выставки.

## Стиль текста для продаж

### Отличия от технических уроков

| Аспект | Технический урок | Урок по продажам |
|---|---|---|
| Фокус | Как устроено | Как продать |
| Термины | Точные определения | Через выгоду клиента |
| Примеры | Расчёты, схемы | Диалоги, ситуации |
| Глаголы | Рассчитайте, проверьте | Предложите, спросите, покажите |
| Таблицы | Технические параметры | Сравнение ценностей по сегментам |

### Тон

Уверенный, но не агрессивный. Менеджер — **эксперт-консультант**, а не «впариватель». Тон: «мы решаем задачу клиента», а не «мы продаём светильники».

### Технические детали в уроках по продажам

Включайте минимум технических деталей — ровно столько, сколько нужно менеджеру, чтобы:

1. Не выглядеть некомпетентным перед инженером клиента
2. Понимать, какой продукт предложить
3. Переключить разговор на ценность для клиента

Если тема требует глубокого технического погружения — дайте кросс-ссылку на технический урок:

```markdown
Подробнее о типах драйверов и протоколах диммирования — [Драйверы и блоки питания LED](lessons/светотехника-драйверы-и-блоки-питания.md).
```

## Чеклист для уроков по продажам

Дополнительно к общему чеклисту из [writing-guide.md](references/writing-guide.md):

- [ ] Каждый сегмент/продукт имеет структурированную карточку (таблица параметров)
- [ ] Есть блок «Что продаём» с ценностями с позиции клиента
- [ ] Есть диалоговые примеры «Клиент — Менеджер»
- [ ] Есть фразы-крючки для каждого сегмента
- [ ] Технические термины объяснены через выгоду
- [ ] Есть сводная таблица в конце крупных секций
- [ ] Есть практические ситуации для разбора
- [ ] Тон — эксперт-консультант, не продавец
