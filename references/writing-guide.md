# Гайд по написанию уроков — EduPlatform

Руководство для авторов технических уроков платформы Group 7Lamp. Описывает структуру, стиль, форматирование и типичные ошибки.

---

## Аудитория

Уроки читают **инженеры-проектировщики, конструкторы и технические специалисты** компании 7Lamp. Уровень подготовки — от стажёров до опытных инженеров.

**Что это значит для автора:**

- Не объясняйте, что такое ватты или вольты (если урок не про основы электротехники)
- Используйте профессиональную терминологию, но расшифровывайте аббревиатуры при первом упоминании
- Давайте практические примеры из светотехники и проектирования
- Привязывайте теорию к реальным задачам 7Lamp

## Структура урока

Каждый урок следует единому шаблону.

### 1. Frontmatter (обязательно)

```markdown
---
title: Точное название урока
category: Проекты
subcategory: Подкатегория
tags: [тег1, тег2, тег3]
---
```

**Правила frontmatter:**

- Блок обёрнут в `---` сверху и снизу
- Между полями **нет пустых строк**
- Все 4 поля обязательны: `title`, `category`, `subcategory`, `tags`
- `tags` — массив в квадратных скобках, через запятую
- Frontmatter идёт **первым** в файле, до любого контента

### 2. Заголовок (H1)

```markdown
# Название урока
```

Совпадает с `title` из frontmatter или является его расширенной формой.

### 3. Вводный абзац

2-3 предложения: **что** узнает читатель и **зачем** ему это нужно. Отвечает на вопрос: «Почему я должен это прочитать?»

**Хорошо:**
> Драйвер — «сердце» светильника. Он преобразует сетевое напряжение в стабильный ток или напряжение для LED. Неправильный выбор драйвера — мерцание, перегрев, преждевременный выход из строя. Этот урок — полное руководство по типам, выбору и подключению драйверов.

**Плохо:**
> В этом уроке мы поговорим о драйверах. Драйверы — это важная тема. Давайте разберёмся.

### 4. Разделитель

```markdown
---
```

Горизонтальная линия `---` между вводным абзацем и первой секцией, а также между всеми секциями. Создаёт визуальные паузы.

### 5. Секции (H2)

Основное содержание урока. Каждая секция — законченный блок по одной подтеме.

```markdown
## Название секции

Контент секции...

---

## Следующая секция
```

### 6. Подсекции (H3)

Детализация внутри секции. Не углубляться дальше H3.

```markdown
### Подтема

Контент...
```

### 7. Вопросы для закрепления (финал)

```markdown
---

## Вопросы для закрепления

1. Вопрос, проверяющий понимание концепции?
2. Вопрос на практическое применение?
3. Вопрос на сравнение или выбор?
```

3-5 вопросов в конце урока. Не тесты с вариантами — открытые вопросы, требующие осмысления.

## Стиль написания

### Тон

Пишите как **опытный наставник** — уверенно, конкретно, без снисходительности. Автор знает тему и делится практическим опытом.

**Хорошо:** «Анодирование не добавляет толщину в привычном смысле — оно "врастает" в металл.»

**Плохо:** «Как вы, наверное, уже знаете, анодирование — это достаточно интересный процесс...»

### Принцип «зачем → как»

Сначала объясните, **зачем** это нужно, потом **как** это работает. Мотивация перед инструкцией.

**Хорошо:**
> Без концепции инженер установил бы равномерное освещение 300 лк по всей площади. С концепцией — три сценария: приглушённый общий свет, акцентный свет на столы, декоративная подсветка. Один объект, принципиально разный результат.

### Длина абзацев

- Один абзац = одна мысль
- 3-5 строк максимум
- Если абзац длиннее — разбейте на два

### Длина предложений

- До 20 слов — идеально
- 20-30 слов — допустимо
- Более 30 слов — разбейте

### Залог

Активный залог. Глаголы действия.

| Плохо | Хорошо |
|---|---|
| Должно быть рассчитано | Рассчитайте |
| Может быть использован | Используйте |
| Освещённость определяется | Определите освещённость |

## Форматирование

### Выделение текста

- **Жирный** — ключевые термины при первом упоминании, важные предупреждения
- *Курсив* — иностранные термины, оговорки, мягкие акценты
- `Код` — значения параметров, имена файлов, команды
- Не злоупотребляйте выделениями — если всё жирное, ничего не выделено

### Таблицы

Используйте для сравнений, характеристик, параметров.

```markdown
| Параметр | CC-драйвер | CV-драйвер |
|---|---|---|
| Стабильность | Отличная | Зависит от нагрузки |
| Применение | Светильники | LED-ленты |
```

### Списки

Маркированные (`*`) — для перечислений без приоритета. Нумерованные (`1.`) — для последовательностей и пошаговых инструкций.

### Блоки кода

Для формул, схем подключения, команд. Указывайте язык после тройных обратных кавычек, если применимо.

### Цитаты-советы

Блоки `>` для практических советов, предупреждений, примеров из реальной работы.

```markdown
> Совет: при малых партиях (до 50 шт.) анодирование дешевле порошковой покраски.
```

```markdown
> Важно: не ориентируйтесь на цвет с экрана монитора. Всегда запрашивайте выкраску.
```

### Заголовки

- `#` — только один, название урока
- `##` — основные секции
- `###` — подсекции
- Не глубже `###`
- Секции можно нумеровать: `## 1. Название`, `## 2. Название`

### Иконки и emoji

- Никаких emoji в тексте уроков
- Иконки платформы — только из библиотеки Lucide

## Кросс-ссылки

Платформа поддерживает ссылки между уроками. Клик открывает урок внутри SPA без перезагрузки.

### Формат ссылки на урок

```markdown
[Основы оптики](lessons/проекты-основы-оптики.md)
```

### Формат ссылки по ID

```markdown
[Основы оптики](lesson:проекты-основы-оптики)
```

ID = имя файла без `.md`.

### Правила

- Ссылка должна вести на реальный файл из `lessons/`
- Если урок ещё не написан — не ставьте ссылку (или пометьте комментарием)
- Используйте кросс-ссылки, когда тема подробно раскрыта в другом уроке

## Ассеты (вложения)

### Размещение

```
assets/<название-без-префикса-категории>/
```

Пример: урок `проекты-анодирование-и-покраска.md` → `assets/анодирование-и-покраска/`

### Ссылки в Markdown

**Картинки:**
```markdown
![Описание изображения](assets/имя-папки/файл.png)
```

**Файлы для скачивания:**
```markdown
[Скачать PDF](assets/имя-папки/файл.pdf)
```

### Правила именования файлов ассетов

- Дефисы вместо пробелов
- Кириллица допускается
- Без подчёркиваний
- Слэши только прямые `/`

---

## Именование файлов уроков

### Формат

```
lessons/<префикс-категории>-<название-через-дефисы>.md
```

### Префиксы

| Категория | Префикс |
|---|---|
| Проекты | `проекты-` |
| Продажи | `продажи-` |

### Правила

- Строчные буквы, кириллица
- Пробелы заменяются дефисами
- Без подчёркиваний, без заглавных букв
- Дефис между префиксом и названием

### Примеры

- `проекты-1-этап-концепция-освещения.md`
- `проекты-4-этап-анодирование-и-покраска.md`
- `продажи-целевые-аудитории.md`

## Чеклист перед публикацией

- [ ] Frontmatter заполнен полностью (title, category, subcategory, tags)
- [ ] Между полями frontmatter нет пустых строк
- [ ] Заголовок H1 есть и совпадает с title
- [ ] Вводный абзац объясняет «зачем» читать урок
- [ ] Разделители `---` между секциями
- [ ] Заголовки не глубже H3
- [ ] Нет стен текста (абзацы по 3-5 строк)
- [ ] Ключевые термины выделены жирным при первом упоминании
- [ ] Таблицы для сравнений, списки для перечислений
- [ ] Практические примеры из светотехники / опыта 7Lamp
- [ ] Нет emoji
- [ ] Есть раздел «Вопросы для закрепления» в конце
- [ ] Имя файла соответствует конвенции
- [ ] Кросс-ссылки ведут на реальные файлы
- [ ] Ассеты размещены в правильной папке

## Типичные ошибки

| Ошибка | Как правильно |
|---|---|
| Пустые строки в frontmatter | Поля без пустых строк между ними |
| Emoji в тексте | Только текст, таблицы, Lucide-иконки |
| Стены текста по 10+ строк | Абзацы по 3-5 строк максимум |
| «В этом уроке мы поговорим о...» | Сразу к сути: «Драйвер — сердце светильника» |
| Пассивный залог | Активный: «рассчитайте», «проверьте» |
| Заголовки H4 и глубже | Максимум H3, перестроить структуру |
| Ссылки на несуществующие уроки | Ссылаться только на существующие файлы |
| Подчёркивания в имени файла | Только дефисы |
